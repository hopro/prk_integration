# PRK Integration — Прикрепление застрахованных лиц к МО

Full-stack приложение (React + FastAPI) для электронного взаимодействия с веб-сервисом ИАС-4 ТФОМС Свердловской области: загрузка прикреплений и проверка страховой принадлежности.

## Архитектура

```
Frontend (React + MUI)  ──HTTP──▶  Backend (FastAPI)  ──SOAP──▶  ИАС-4 (внешний сервис)
    :3001 (nginx)          :8001                        10.0.100.5
                               ├──▶ Шлюз ЕЦП ──▶ ЕЦП (participant card)
                               └──▶ SQLite + файлы справочников
                                     settings.db, dictionaries.db, prk_history.db
                                     tfoms/SPMO.zip, SPSMO.zip, SPDEPT.xml
```

## Развёртывание и обновление

Полная инструкция для администратора: **[deploy/ИНСТРУКЦИЯ.md](deploy/ИНСТРУКЦИЯ.md)**.
Текущая версия — в файле [`VERSION`](VERSION), что изменилось — в
[`CHANGELOG.md`](CHANGELOG.md).

### Установка

```bash
git clone <адрес-репозитория> prk_integration
cd prk_integration
mkdir -p tfoms && cp /путь/к/файлам/*.zip /путь/к/файлам/*.xml tfoms/
cp .env.example .env        # задать 4 обязательных значения
docker compose up -d --build
```

Система откроется на `http://<адрес-сервера>:3001`. Проверка:

```
http://<адрес-сервера>:3001/api/v1/auth/gateway-health
```

### Обновление

```bash
git pull
docker compose up -d --build
```

Настройки, справочники и история сохраняются: `.env`, каталог `${DATA_DIR}` и
тома баз не входят в git.

### Переменные окружения

Все настройки — в `.env`, образец в `.env.example`. Обязательны четыре:
`GATEWAY_DB_PASSWORD`, `JWT_SECRET_KEY`, `GATEWAY_LOGIN`, `GATEWAY_PASSWORD`.
`MIS_GATEWAY_URL` задавать не нужно — compose подставляет `http://gateway:8010`.

Порты: наружу открыт только интерфейс `APP_PORT` (по умолчанию 3001). Backend и
шлюз доступны внутри сети compose, на хост не выведены.

## Страницы приложения

### Прикрепление ЗЛ
Загрузка сведений о прикреплении застрахованного лица к медицинской организации через SOAP-сервис LoadPrk.

### Проверка полиса
Онлайн-проверка страховой принадлежности и прикрепления через SOAP-сервис GetInsPrkState.

### Сопоставление участков
Связка кодов подразделений ИАС-4 с участками ЕЦП. Нужна потому, что нумерация
у них разная: автоматически совпадают единицы из десятков, остальное проставляет
администратор вручную. Подробности — в
[deploy/dictionaries/README.md](deploy/dictionaries/README.md).

## Авторизация ИАС-4

Учётные данные для доступа к внешнему SOAP-сервису (ИАС-4) вводятся через диалог «Настройки» (иконка шестерёнки в шапке приложения).

| Поле | Описание |
|------|----------|
| Имя пользователя ИАС-4 | Логин, выданный администратором системы |
| Пароль ИАС-4 | Пароль пользователя ИАС-4 |
| Код МО по умолчанию | Код медицинской организации (по умолчанию `0893`) |

Настройки хранятся в базе данных SQLite (`backend/settings.db`) на стороне сервера и доступны с любого ПК.

> **Важно:** Логин и пароль — это реальные учётные данные пользователя ИАС-4. Доступ к SOAP-сервису предоставляется администратором ТФОМС.

## Справочники

Справочники хранятся в локальной БД `dictionaries.db` и загружаются на вкладке
«Справочники» из файлов. Внешние базы данных не нужны.

| Справочник | Источник | Что используется |
|------------|----------|------------------|
| Участки ЛПУ | ЕЦП, `getLpuRegion` | поиск `LpuRegion_id` при сохранении карты |
| Подразделения МО | `SPDEPT.xml` (`.zip`/`.csv`) | код `podr` в форме прикрепления |
| Медицинские организации | `SPMO.zip` | выбор МО |
| Страховые компании | `SPSMO.zip` | выбор СМО |

### Почему для `podr` нужен отдельный справочник ИАС-4

Код подразделения, который ИАС-4 принимает в поле `podr`, берётся **только** из
справочника подразделений ИАС-4. Участки ЕЦП для этого не подходят: у ЕЦП своя
нумерация.

Сверка на ГП № 4 (МО 893), ЛПУ 13003795 — 79 кодов в справочнике ИАС-4 против
107 участков ЕЦП:

| Источник | Кодов | ИАС-4 знает |
|----------|-------|-------------|
| Участки ЕЦП с суффиксом `_ГРП` | 40 | **0** |
| Участки ЕЦП с суффиксом `_ГП3` | 27 | 7 |
| Участки ЕЦП с голым кодом | 40 | 36 |

Поэтому подразделение, названное в ЕЦП «ОВП № 1 п.Новоасбест 531000_ГРП», нельзя
отправлять как `podr=531000` — ИАС-4 отвечает 501 «отсутствует в справочнике». В
справочнике ИАС-4 то же подразделение — `700200`, и оно принимается.

Без файла `SPDEPT.xml` форма прикрепления не может предложить корректный список и
сообщает об этом явно. Участки ЕЦП при этом не теряются: по коду подразделения из
ИАС-4 находится соответствующий участок ЕЦП для сохранения карты. Сопоставление идёт
по нормализованному имени, суффиксы и регистр не учитываются. Покрытие видно на
вкладке «Справочники» и в `GET /api/dict/spdept/coverage`.

### Настройка

| Переменная | Описание | По умолчанию |
|------------|----------|--------------|
| `DICT_DB_PATH` | Путь к базе справочников | `/app/app/data/dictionaries.db` |
| `TFOMS_DIR` | Каталог с файлами справочников | `/app/tfoms` |
| `TFOMS_ENCODING` | Кодировка XML-выгрузок | `cp1251` |

## Проверка связи со шлюзом

```
GET /api/v1/auth/gateway-health
```

Разбирает связь backend → шлюз по шагам `resolve`, `tcp`, `probe`, `login` и в
поле `hint` пишет, что чинить. Проверять и ЕЦП, и настройку адреса не нужно.

## SOAP-сервисы

| Сервис | URL | Операция |
|--------|-----|----------|
| LoadPrk | `10.0.100.5/IASWeb/LoadPrk/LoadPrk.asmx` | Загрузка прикреплений |
| InsCheck | `10.0.100.5/IASWeb/InsCheck/InsCheck.asmx` | Проверка полиса |

Настройка URL сервисов — в `backend/.env`:

| Переменная | Описание | По умолчанию |
|------------|----------|--------------|
| `SOAP_URL` | URL LoadPrk | `http://10.0.100.5/IASWeb/LoadPrk/LoadPrk.asmx` |
| `SOAP_CHECK_URL` | URL InsCheck | `http://10.0.100.5/IASWeb/InsCheck/InsCheck.asmx` |

SOAPAction заданы константами сервисов и настраиваются через диалог настроек
(`http://tfoms.e-burg.ru/srv_loadprk/LoadPrk`, `http://tempuri.org/GetInsPrkState`).

Адреса ИАС-4 и шлюза ЕЦП задаются через UI и хранятся в SQLite, чтобы их можно было
поменять без перезапуска контейнеров.

Для тестирования:
```
SOAP_URL=http://10.0.100.5/IASWeb/LoadPrkTest/LoadPrk.asmx
```

## API

### Словари

| Метод | Endpoint | Описание |
|-------|----------|----------|
| GET | `/api/dict` | МО и СМО |
| GET | `/api/dict/spdept?mo=893` | Подразделения ИАС-4 для поля `podr` |
| GET | `/api/dict/spdept/coverage` | Сколько подразделений привязано к участкам ЕЦП |
| GET | `/api/dictionaries/region-links` | Таблица сопоставления подразделений и участков |
| POST | `/api/dictionaries/region-links` | Привязать или отвязать код подразделения |
| GET | `/api/dictionaries/region-links/suggest` | Предложения автоматического подбора |
| POST | `/api/dictionaries/region-links/apply` | Применить автоматический подбор |
| GET | `/api/dictionaries/status` | Состояние справочников |
| POST | `/api/dictionaries/load` | Загрузить: участки из ЕЦП или файл ТФОМС |
| POST | `/api/dictionaries/upload` | Загрузить файл справочника |
| GET | `/api/settings` | Текущие настройки |
| POST | `/api/settings` | Сохранить настройки |

### Прикрепление

| Метод | Endpoint | Описание |
|-------|----------|----------|
| POST | `/api/prk/load` | Отправить прикрепление |

**Тело запроса:**
```json
{
  "login": { "user": "логин", "password": "пароль" },
  "person": {
    "fam": "Иванов",
    "im": "Иван",
    "ot": "Иванович",
    "dr": "1993-01-10",
    "vpolis": 3,
    "npolis": "6687399776000583"
  },
  "prk_list": [
    { "typeprk": 1, "mo": 893, "podr": "43500", "dbeg": "2026-07-02", "meth": 2 }
  ]
}
```

### Проверка полиса

| Метод | Endpoint | Описание |
|-------|----------|----------|
| POST | `/api/ins-check/check` | Проверить страхование |

**Формат СНИЛС:** `999-999-999 99` (11 цифр с дефисами и пробелом). Пример: `162-136-164 34`.

> **Ошибка 107** — неверный формат СНИЛС. Сервис ИАС-4 требует формат `XXX-XXX-XXX YY`.

## Стек технологий

- **Frontend:** React 18, TypeScript, Vite 6, Material UI 6, Axios
- **Backend:** Python 3.12, FastAPI, httpx, defusedxml, pydantic
- **Базы данных:** SQLite — настройки, справочники, история прикреплений
- **Инфраструктура:** Docker, Docker Compose, nginx

│   └── Dockerfile
├── gateway/

│   │   ├── auth/               # вход в шлюз, учётные данные ЕЦП

Один `docker-compose.yml` на всё: при клонировании репозитория и при сборке
комплекта из него используется одна и та же топология.

## Разработка без Docker

**Backend:**
```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

**Frontend:**
```bash
cd frontend
npm install
npm run dev
```
