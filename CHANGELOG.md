# История изменений

Номера версий соответствуют содержимому файла `VERSION`. Перед обновлением
посмотрите этот файл — здесь написано, что изменилось и требует ли действий.

Обновление описано в [deploy/ИНСТРУКЦИЯ.md](deploy/ИНСТРУКЦИЯ.md). Оно сводится
к двум командам: `git pull` и `docker compose up -d --build`.

## 1.3.0

### Что сделано

- **Справочник ФАПов `SPSUBDEPT`.** Второй справочник подразделений ИАС-4: ФАПы,
  медкабинеты и дневные стационары. Для ГП № 4 — 52 подразделения, из них 21 с
  признаком «разрешено прикрепление». Коды из него идут в то же поле `podr`, что и
  обычные подразделения, и коды двух справочников не пересекаются, поэтому таблица
  связей остаётся одна.
- **Подразделения ИАС-4 показываются в одном списке с пометкой источника:**
  «подразделение» или «ФАП». В форме прикрепления для МО 893 доступно 100
  подразделений: 79 обычных и 21 ФАП.
- **Недоступные подразделения убраны из таблицы.** Из 145 подразделений МО 893
  показываются 100: ещё 31 имеют `PRKYES = 0` (ИАС-4 отвечает 502) и 14 — истёкший
  срок действия (501). Галочка «показать недоступные» открывает полный список.
- **Убраны счётчики «Битых привязок», «Отвязано намеренно» и «Закрытых
  подразделений»:** они требовали пояснений, а состояние видно прямо в таблице.
  Остались «Подразделений ИАС-4», «Привязано», «Не привязано», «Из них ФАПов» и
  «Участков ЕЦП занято».
- **Справочник ФАПов появился на вкладке «Справочники»** отдельной карточкой
  «ФАПы и прочие подразделения (SPSUBDEPT)» с кнопками «Обновить из XML» и
  «Загрузить XML».
- **Участок ЕЦП показан как `LpuRegion_Name` и `LpuRegion_Descr`**, без
  идентификатора: он не несёт смысла для человека, а нужен только при отправке.
- **Сопоставление сначала по цифрам из названия участка, затем по названию
  подразделения.** Цифры находят 36 подразделений, названия — ещё 45, включая
  ФАПы: у них коды в ЕЦП не встречаются вовсе (имя участка — `523102_ГРП`), и
  совпадение есть только по описанию. Сравнение названий идёт без учёта пробелов и
  точек: «Модульный ФАП п. Зональный» и «ФАП п.Зональный» — одно подразделение.
  Всего для ГП № 4 находится 82 привязки из 114, включая 18 ФАПов.
- **Код МО для SPSUBDEPT ищется по окончанию:** в нём код записан длиннее
  (`660893` против `893`), отдельная настройка не нужна.

### Требует действий администратора

Положите в `./tfoms` файл `SPSUBDEPT.xml` и обновите оба справочника подразделений
на вкладке «Справочники». Файл должен называться именно `SPSUBDEPT.xml`: по
содержимению он неотличим от SPDEPT, различает их только имя.

Затем на вкладке «Сопоставление участков» нажмите «Подобрать автоматически» →
«Применить» и доведите «Не привязано» до нуля.

Подробности — в `deploy/dictionaries/README.md`, пошагово — в `deploy/ИНСТРУКЦИЯ.md`.

## 1.2.0

### Что сделано

- **Вкладка «Сопоставление участков».** Администратор вручную связывает каждый код
  подразделения ИАС-4 с участком ЕЦП. Раньше соответствие угадывалось по названию,
  и у ГП № 4 это давало верный результат для единиц из десятков: все коды с
  суффиксом `_ГРП` в справочнике ИАС-4 не встречаются, поэтому такие подразделения
  прикреплялись наугад и ЕЦП получал не тот участок.
- **Ручная привязка важнее автоматики.** Порядок выбора: ручная привязка →
  осознанная отвязка → автоматический подбор → «не найдено».
- **Осознанная отвязка.** Кнопка снимает привязку и оставляет пометку: автоподбор
  больше не предлагает этот код. Рядом — возврат в автоматический подбор.
- **Кнопка «Подобрать автоматически».** Показывает предложения и применяет их
  отдельной кнопкой, чтобы администратор успел проверить. Ручные привязки не
  затрагиваются.
- **Счётчики и «битые» привязки.** Если привязанный участок исчез из ЕЦП, страница
  это показывает, а прикрепление получает понятную ошибку вместо чужого
  `LpuRegion_id`.
- **Список свободных участков** с подсказкой, какому коду участок подходит.
- **Привязки переживают обновление и повторную загрузку справочников**: они лежат в
  `${DATA_DIR}/dictionaries.db`.

- **СПФМО (`SPFMODIVISION.zip`) убран из системы.** В выгрузке 160 тысяч
  подразделений по всей стране, кода медицинской организации в ней нет, а
  совпадения с подразделениями конкретного МО единичны и приблизительны.
  Смотреть такой список было нечем, а страница от его показа зависала. Справочник
  подразделений ИАС-4 (`SPDEPT.xml`) содержит нужное, поэтому он и остался.
- **Сопоставление ищет по описанию участка.** У ЕЦП заполнено `LpuRegion_Descr`
  («Терапевтический участок 1» для участка с именем `20100»), и по нему
  подразделение находится, когда имя — код. На странице сопоставления видны и
  `LpuRegion_Name`, и `LpuRegion_Descr`. Автоподбор находит 36 подразделений из 79
  для МО 893.
- **Подразделения грузятся как остальные XML-выгрузки:** «Обновить из XML» из
  каталога `./tfoms`, а не только загрузкой файлом.
- **Справочник ограничен вашим МО.** В выгрузке 159 организаций, показывались
  подразделения всех сразу; теперь берутся подразделения МО из настроек.
- **Закрытые подразделения отмечены.** Из 93 подразделений МО 893 актуальны 79;
  остальные помечены на странице сопоставления и не попадают в форму выбора —
  ИАС-4 их не примет.

### Требует действий администратора

1. Обновите справочник подразделений ИАС-4: вкладка «Справочники» →
   «Подразделения МО (справочник ИАС-4)» → «Обновить из XML».
2. Загляните на вкладку «Сопоставление участков» и доведите счётчик
   «Не привязано» до нуля. Без этого прикрепление продолжит подставлять участок по
автоподбору, а для кодов вида `*_ГРП` — неправильно.

Порядок: загрузить `SPDEPT.xml` → обновить участки из ЕЦП → «Подобрать
автоматически» → «Применить» → доправить остальное вручную.

Подробности — в `deploy/dictionaries/README.md`, пошагово — в
`deploy/ИНСТРУКЦИЯ.md`.

## 1.1.0

### Для кого эта версия

Если система у вас уже работает, а нужно только получить новые справочники или
исправить адрес шлюза — вам достаточно команд из инструкции, делать руками
ничего не нужно.

Если при обновлении появится сообщение про `MIS_GATEWAY_URL`, про старые
контейнеры или про смену пароля базы — это относится к переходу со старой
версии, см. раздел «Миграция со старой версии».

### Исправлено

- **Код подразделения для ИАС-4 берётся из справочника ИАС-4, а не из названий
  участков ЕЦП.** Раньше выбор подразделения подставлял код из названия участка
  ЕЦП, и ИАС-4 отвечал отказом 501 «участок отсутствует в справочнике». Из 40
  участков ЕЦП с суффиксом `_ГРП` в справочнике ИАС-4 не было ни одного.
  Теперь коды берутся из файла `SPDEPT.xml`.

  **Что сделать:** положить `SPDEPT.xml` в `./tfoms` и загрузить его на вкладке
  «Справочники». Подойдёт `.xml`, `.zip` или `.csv` с колонками кода и названия.
  Пока файла нет, форма прикрепления прямо сообщает, что справочник не загружен.

- **Внешняя СУБД убрана из проекта.** Справочники хранятся локально, в
  `${DATA_DIR}/dictionaries.db`, и загружаются из файлов.

- **Адрес шлюза больше не берётся из `.env` по умолчанию.** Если в `.env` лежал
  адрес машины, на которой систему в последний раз запускали вручную, backend
  ходил не туда и получал `404 {"detail":"Not Found"}`. Теперь compose
  подставляет `http://gateway:8010`, а в `.env` значение нужно задавать только
  для действительно внешнего шлюза.

- **Понятная ошибка вместо пустой.** Раньше в интерфейсе появлялось
  «Шлюз не принял адрес ЕЦП: » без объяснения. Теперь сообщение называет
  адрес, на который ушло соединение, и что с ним не так.

- **Интерфейс не падает при перезапуске backend.** Раньше nginx не мог разрешить
  имя контейнера и уходил в цикл перезапуска, из-за чего весь интерфейс был
  недоступен.

- **Незаполненный `.env` останавливает развёртывание** с внятным сообщением
  вместо запуска с паролями из примера.

- **Уточнена диагностика.** `GET /api/v1/auth/gateway-health` разбирает связь
  backend → шлюз по шагам и называет вердикт: шлюз доступен, вход не удался,
  адрес указывает на сам backend или по адресу отвечает другая программа.

### Требует внимания при обновлении

1. `SPDEPT.xml` — без него не будет кодов подразделений для поля `podr`.
2. `GATEWAY_DB_PASSWORD` задаётся только при первом запуске. Если меняете его
   в `.env` на уже работающей системе — менять пароль в самой базе, иначе шлюз
   не поднимется.
3. **В этой версии впервые меняется имя сети и имя проекта compose.** Раньше они
   были заданы явно, из-за чего обновление могло упасть с «port is already
   allocated», а при нескольких установках на одном сервере интерфейс показывал
   чужую систему. Теперь имена берутся из имени каталога. Если обновление
   завершилось ошибкой — **повторите ту же команду**: контейнеры пересоздадутся,
   данные не пострадают. Подробности в разделе 7 инструкции.
