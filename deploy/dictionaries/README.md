# Справочники системы

Справочники берутся из двух источников:

| Справочник                | Источник                    | Как загрузить                          |
|---------------------------|-----------------------------|----------------------------------------|
| Участки ЛПУ               | ЕЦП (`getLpuRegion`)        | кнопка «Обновить из ЕЦП»               |
| Подразделения МО (ИАС-4)  | `SPDEPT.xml` / `.zip` / `.csv` | кнопка «Обновить из XML»             |
| ФАПы (SPSUBDEPT)         | `SPSUBDEPT.xml` / `.zip`      | кнопка «Обновить из XML»             |
| Мед. организации          | `SPMO.zip`                  | кнопка «Обновить из XML»               |
| Страховые компании        | `SPSMO.zip`                 | кнопка «Обновить из XML»               |

## XML-выгрузки ТФОМС

Файлы `SPSMO.zip`, `SPMO.zip`, `SPDEPT.xml`, `SPSUBDEPT.xml` кладутся в каталог `./tfoms`
рядом с `docker-compose.yml` и монтируются в контейнер только на чтение.
Кнопка «Загрузить» сама найдёт нужный файл; можно и загрузить его вручную
кнопкой «Из файла».

Формат одинаковый: ZIP с одним XML в кодировке **windows-1251**, корневой
элемент `ROOT`, записи `<REC …/>`. Вид справочника определяется по имени файла,
а при неоднозначности — по атрибутам записей.

### SPSMO.zip — страховые компании

| Атрибут | Смысл            |
|---------|------------------|
| `CODE`  | Код СМО          |
| `NAME`  | Наименование     |
| `MAIL`  | Почта            |

### SPMO.zip — медицинские организации

| Атрибут    | Смысл            |
|------------|------------------|
| `CODE`     | Код МО           |
| `NAME`     | Наименование     |
| `TERR`     | Код территории   |
| `ADDRESS`  | Адрес            |

На один код МО приходится несколько записей (филиалы, адреса) — они
сливаются: пустое значение дополняется непустым из другой записи.

### Что сделано вместо этого

Просмотр справочника постраничный: 200 записей на страницу. Раньше окно
запрашивало весь справочник целиком и браузер висел на нём несколько минут.
Теперь страница открывается меньше чем за секунду, а пагинация, поиск и фильтры
работают по всей базе.

| Инструмент | Что делает |
|------------|-----------|
| Поиск по коду и названию | сужает выдачу до нужных записей |
| Фильтр «Вид подразделения» | 642 вида с числом записей: ФАП, поликлиники, стоматологические и прочие. Вид хранится в `VID_SPMO` |
| **«Только мои МО»** | подбирает записи по совпадению названий с подразделениями ИАС-4 вашего МО |
| Постраничная навигация | счётчик «показано 200 из 158 241» |

Режим «Только мои МО» работает так: берутся подразделения вашего МО из
справочника ИАС-4, названия нормализуются (пробелы, точки и знаки
препинания отбрасываются: «ОВП № 1 п. Новоасбест» → `овпнновоасбест`) и
сравниваются с названиями из СПФМО. Совпадение засчитывается при точном
совпадении или совпадении по началу, если общая часть не короче 14 символов —
иначе «Терапевтический» нашлось бы тысячи раз.

Результат отсортирован по тому, насколько редко название встречается в СПФМО:
«ОВП 1 п. Новоасбест ПО №7» встречается один раз и попадает наверх, а
«СТОМАТОЛОГИЧЕСКАЯ ПОЛИКЛИНИКА» — сотни раз по всей стране и уходит вниз.
Колонка «Код ИАС-4» показывает, к какому подразделению относится запись.

Совпадения приблизительные: разные справочники расходятся в написании. Точную
связь подразделения с участком задаёт вкладка «Сопоставление участков», а
СПФМО остаётся источником названий.

## Что внутри SPDEPT.xml

Выгрузка ИАС-4 со справочником подразделений: 6633 записи по 159 медицинским
организациям. Поля записи:

| Поле | Содержание |
|------|-----------|
| `MO` | код медицинской организации |
| `PODR` | код подразделения — именно он уходит в поле `podr` |
| `CODE` | номер подразделения внутри МО, **не путать с `PODR`** |
| `NAME` | краткое название: «Участок №6» |
| `LONGNAME` | полное название: «Терапевтический участок №6» |
| `PRKYES` | признак «разрешено прикрепление» — тот самый, на который ИАС-4 отвечает ошибкой 502 |
| `DBEGIN`, `DEND` | период действия |

Что из этого используется:

- `scope` записи — код МО, поэтому подразделения разных организаций лежат рядом, но не смешиваются;
- `valid_until` — дата из `DEND`; `31.12.2999` считается открытым периодом;
- название для сопоставления — `LONGNAME`, он ближе к тому, как подразделение
  называют в ЕЦП.

Длина `PODR` разная: у МО 893 — пять цифр (`31400`), у других — до восьми
(`20100600`).

Закрытые подразделения из выгрузки не удаляются, но и в форме выбора их нет:
у МО 893 из 93 записей актуальны 79, остальные 14 помечены на странице
сопоставления как закрытые. ИАС-4 закрытое подразделение не примет.

## SPSUBDEPT: ФАПы и прочие подразделения

Второй справочник подразделений ИАС-4. От SPDEPT формат записей не отличается, но
содержит ФАПы, медкабинеты и дневные стационары. Для ГП № 4 — 52 подразделения, из
них 21 с признаком «разрешено прикрепление» и адресом.

| Отличие от SPDEPT | Значение |
|-------------------|----------|
| Код МО записан длиннее | `660893` против `893`, поэтому код из настроек ищется по окончанию |
| Есть `ADDRESS` | адрес подразделения, заполнен у большинства записей |
| Есть `DEPT` | уровень подразделения |
| `PRKYES` | у 31 из 52 равен 0 — ИАС-4 такие отклоняет с кодом 502 |

**Различать файлы можно только по имени.** Записи у двух справочников одинаковые,
и по содержимому SPSUBDEPT неотличим от SPDEPT. Называйте файл `SPSUBDEPT.xml`
или `SPSUBDEPT.zip`; при другом имени он загрузится как обычные подразделения.

Коды подразделений в двух выгрузках не пересекаются, поэтому таблица связей одна.

## Сопоставление подразделений ИАС-4 с участками ЕЦП

Код подразделения уходит в ИАС-4 как `podr`, а участок ЕЦП нужен, чтобы сохранить
карту пациента при отправке. Это две разные нумерации, и совпадают они единицы из
десятков: у ГП № 4 из 107 участков ЕЦП ни один код с суффиксом `_ГРП` в
справочнике ИАС-4 не встречается.

Участок ЕЦП описан двумя полями, и сопоставление смотрит на оба:

| Поле ЕЦП | Пример | Зачем |
|----------|--------|-------|
| `LpuRegion_Name` | `20100` | имя участка, часто является кодом |
| `LpuRegion_Descr` | `Терапевтический участок 1` | смысл подразделения: у всех 107 участков заполнено |

Описание полезнее имени: участок с именем `20100` описывается как «Терапевтический
участок 1», и по описанию он находится в справочнике ИАС-4, где подразделение
названо словами. Поэтому автоподбор проверяет и имя, и описание — так у МО 893
находятся 36 подразделений из 79 без участия человека.

Поэтому соответствие проставляет администратор на вкладке **«Сопоставление
участков»** — один раз, вручную, и оно действует постоянно.

| Что показывает страница | Зачем |
|------------------------|-------|
| Счётчики: подразделений, привязано, не привязано, отвязано намеренно, битых привязок | видно, сколько ещё работы осталось |
| Список кодов ИАС-4 с выпадающим выбором участка ЕЦП | основная работа |
| Метка способа: `вручную`, `автоматически`, `отвязано`, `участок исчез из ЕЦП` | видно, где решение принято человеком |
| Отдельный список свободных участков ЕЦП | понимаете, что осталось незадействованным |
| Кнопка «Подобрать автоматически» | экономит время на совпадениях, которые нашлись сами |

### Как это работает при отправке прикрепления

1. **Ручная привязка.** Если код привязан администратором, берётся именно этот
   участок.
2. **Осознанная отвязка.** Если администратор снял привязку кнопкой, участок не
   подставляется вовсе — автоподбор больше не будет предлагать этот код.
3. **Автоматический подбор** по названию, если ручной привязки нет.
4. Ничего не нашлось — прикрепление уходит в ЕЦП без участка, и в истории
   появляется объяснение с подсказкой привязать код вручную.

Участок не подставляется наугад: если привязанный участок исчез из ЕЦП после
обновления справочника, страница помечает привязку как битую, а прикрепление
получает понятную ошибку вместо чужого `LpuRegion_id`.

### Как заполнить быстро

1. Загрузите `SPDEPT.xml` и `SPSUBDEPT.xml`, обновите участки из ЕЦП.
2. Нажмите **«Подобрать автоматически»** и **«Применить»** — совпадения по коду в
   названии участка (например, `20100` → участок «20100») применятся сразу.
3. Остальное доделайте вручную: там, где участок назван текстом с суффиксом
   `_ГРП`, кода в названии нет и автоматика не справится.

Порядок сопоставления:

1. **цифры из `LpuRegion_Name`** — участок с именем `21100` и кодом подразделения
   `21100`; для ГП № 4 так находятся 36 подразделений;
2. **название подразделения** против названия и описания участка, без учёта
   пробелов и точек — так находятся ФАПы: «Модульный ФАП п. Зональный» и
   «ФАП п.Зональный» это одно и то же подразделение. Ещё 45;
3. прочие совпадения по названию и описанию.

Итого для ГП № 4 автоматически находится 82 подразделения из 114, включая 18 ФАПов.

Привязки хранятся в `${DATA_DIR}/dictionaries.db` и переживают обновление и
повторную загрузку обоих справочников. Если код в `SPDEPT.xml` сменился, старую
привязку нужно поставить заново.

То же самое доступно через API:

| Метод | Endpoint | Назначение |
|-------|----------|-----------|
| GET | `/api/dictionaries/region-links` | таблица сопоставления; `includeForbidden=true` показывает запрещённые |
| POST | `/api/dictionaries/region-links` | привязать или отвязать |
| POST | `/api/dictionaries/region-links/forget` | снять привязку полностью |
| GET | `/api/dictionaries/region-links/suggest` | что предложил бы автоподбор |
| POST | `/api/dictionaries/region-links/apply` | применить автоподбор |
| GET | `/api/dict/spdept/coverage` | сводка привязок |
| GET | `/api/dictionaries/entries` | страница справочника: `limit`, `offset`, `search`, `scope`, `total` |

## Если файлов ТФОМС нет

Справочник СПМО/СМО можно загрузить из CSV — кнопка «Из файла», разделитель `;`
или `,`. Для СПМО обязательны колонки `code` и `name`. `regions.csv` в этом
каталоге — пример формата для участков.
