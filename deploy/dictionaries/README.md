# Справочники системы

Справочники берутся из двух источников:

| Справочник                | Источник                    | Как загрузить                          |
|---------------------------|-----------------------------|----------------------------------------|
| Участки ЛПУ               | ЕЦП (`getLpuRegion`)        | кнопка «Обновить из ЕЦП»               |
| Подразделения МО (ИАС-4)  | `SPDEPT.xml` / `.zip` / `.csv` | кнопка «Загрузить файл»             |
| Мед. организации          | `SPMO.zip`                  | кнопка «Обновить из XML»               |
| Страховые компании        | `SPSMO.zip`                 | кнопка «Обновить из XML»               |
| Подразделения МО (СПФМО)  | `SPFMODIVISION.zip`         | кнопка «Обновить из XML»               |

## XML-выгрузки ТФОМС

Файлы `SPSMO.zip`, `SPMO.zip`, `SPFMODIVISION.zip` кладутся в каталог `./tfoms`
рядом с `docker-compose.yml` и монтируются в контейнер только на чтение.
Кнопка «Загрузить» сама найдёт нужный файл; можно и загрузить его вручную
кнопкой «Из файла».

Формат одинаковый: ZIP с одним XML в кодировке **windows-1251**, корневой
элемент `ROOT`, записи `<REC …/>`. Вид справочника определяется по имени файла,
а при неоднозначности — по атрибутам записей.

### SPSMO.zip — страховые компании

| Атрибут | Смысл            |
|---------|------------------|
| `CODE`  | Код СМО          |
| `NAME`  | Наименование     |
| `MAIL`  | Почта            |

### SPMO.zip — медицинские организации

| Атрибут    | Смысл            |
|------------|------------------|
| `CODE`     | Код МО           |
| `NAME`     | Наименование     |
| `TERR`     | Код территории   |
| `ADDRESS`  | Адрес            |

На один код МО приходится несколько записей (филиалы, адреса) — они
сливаются: пустое значение дополняется непустым из другой записи.

### SPFMODIVISION.zip — подразделения МО

| Атрибут       | Смысл                                  |
|---------------|----------------------------------------|
| `IDSPMO`      | Идентификатор подразделения           |
| `NAM_SPMO`    | Наименование подразделения            |
| `NAM_SK_SPMO` | То же краткое наименование            |
| `VID_SPMO`    | Вид подразделения                     |
| `DATEBEG` / `DATEEND` | Период действия              |

В выгрузке около 160 тысяч записей по всей стране и **нет привязки к коду МО**,
поэтому она отвечает за названия, а не за коды.

## Справочник подразделений ИАС-4 (SPDEPT) — обязателен

Код подразделения, который ИАС-4 принимает в поле `podr`, берётся **только** из
этого справочника. Список участков ЕЦП для этого не годится: у ЕЦП своя
нумерация.

Сверка на ГП № 4 (код МО 893), ЛПУ 13003795:

| Источник                  | Кодов | ИАС-4 знает      |
|---------------------------|-------|------------------|
| Участки ЕЦП, с суффиксом `_ГРП` | 40  | **0**           |
| Участки ЕЦП, с суффиксом `_ГП3` | 27  | 7                |
| Участки ЕЦП, голый код         | 40  | 36               |
| Справочник ИАС-4 (SPDEPT)       | 79  | все              |

Из-за подстановки кодов из названий ЕЦП подразделение вида
`531000` (название ЕЦП «ОВП № 1 п.Новоасбест 531000_ГРП») приходило выбирать как
`podr`, и ИАС-4 отвечал:

- `501` — «Участок/пункт отделение МО отсутствует в справочнике»
- `502` — «У участка МО отсутствует признак "Разрешено прикрепление"»

При этом в справочнике ИАС-4 то же подразделение называется иначе и имеет другой
код (`700200` — «ОВП № 1 п. Новоасбест»).

Без файла SPDEPT форма прикрепления не может предложить корректный список: система
прямо сообщает, что справочник не загружен.

Участки ЕЦП при этом никуда не делись — они нужны, чтобы по коду подразделения
найти `LpuRegion_id` при сохранении карты в ЕЦП. Сопоставление идёт по
нормализованному имени: `31400` находит участок ЕЦП `31400_ГП3`, суффиксы и
регистр не учитываются. Покрытие видно на вкладке «Справочники» и в
`GET /api/dict/spdept/coverage`.

## Если файлов ТФОМС нет

Справочник СПМО/СМО можно загрузить из CSV — кнопка «Из файла», разделитель `;`
или `,`. Для СПМО обязательны колонки `code` и `name`. `regions.csv` в этом
каталоге — пример формата для участков.
